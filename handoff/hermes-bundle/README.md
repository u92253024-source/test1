# Hermes 交接包：使用說明

## 包裡有什麼
| 路徑 | 用途 | 放到哪 |
|---|---|---|
| `AGENTS.md` | 專案背景、已定案決定、絕對規則（精簡） | 專案資料夾根目錄 |
| `memory/USER.md`、`memory/MEMORY.md` | 極短的長期記憶 | Hermes 記憶資料夾 |
| `skills/community-ops/` | 常用作業流程（信件、問卷分析、聚會規劃、簡報） | Hermes skills 資料夾 |
| `history/` | 時間線、決定理由、踩過的坑、檔案清單 | 專案資料夾，**平時不載入，需要才讀** |

設計原則：**常駐的越短越好，詳細的放 history 讓它按需讀取**。長記憶會擠掉工作空間。

## 一步一步
以下路徑與指令依 Hermes Agent 官方文件整理，**我沒能在這裡實際安裝驗證**，執行前請對照 https://hermes-agent.nousresearch.com/docs ，文件有提供給機器讀的 llms.txt 可查最新用法。

1. **安裝並設定 Hermes**，確認它能在您的電腦正常對話。
2. **建立專案資料夾**，把 `AGENTS.md` 與 `history/` 放進去，並在這個資料夾內啟動 Hermes。官方文件列出的背景檔包含 AGENTS.md，會注入系統提示。
3. **複製記憶**：`memory/` 內兩個檔案放到 `~/.hermes/memories/`（此路徑來自第三方文章，請以官方文件為準）。若有字數上限，保留 MEMORY.md 即可。
4. **複製技能**：把 `skills/community-ops/` 放到 `~/.hermes/skills/`。
5. **驗收**，依序問它以下三題：
   - 「請說出專案現況與下一步。」→ 應提到一個核心社群＋三軌、第一專案是學分抵免詢答。
   - 「幫我擬第三次聚會（資料整理與試算表）的邀請信草稿。」→ 應用既有信件結構，日期留 ○月○日，含退出台階，且不自行寄出。
   - 「把問卷回覆逐人列出來。」→ 應拒絕或提醒個資，這代表規則有生效。
6. 三題都通過再開始日常使用。

## 建議的導入順序（呼應 Human-in-the-loop）
| 階段 | 讓它做什麼 | 不要做什麼 |
|---|---|---|
| 第 1–2 週 | 只讀、只擬稿：信件草稿、簡報大綱、會議紀錄整理 | 不給寄信或發佈權限 |
| 第 3–4 週 | 協助資料整理：抵免辦法、常見問答的結構化 | 不貼學生個資 |
| 之後 | 排程提醒（例如聚會前一週提醒）、週期性彙整 | 對外動作一律由您按下 |

## 您需要自己備妥的
- 簡報、講者小抄、示範腳本、10/7 邀請信（只在您本機）。
- 問卷回覆 Excel：**不要交給 Hermes**，需要分析時貼去識別化的整體數字。
- 任何 API 金鑰與帳號：不要寫進包內。

## 關於「完整對話紀錄」
我無法從雲端匯出原始逐字對話。本包是整理後的版本，對 bot 反而更有效。若您仍要原文，轉到本機並接續本次對話後，Claude Code 會把紀錄存在本機（通常在 `~/.claude/projects/` 下的 .jsonl 檔，位置依版本而異），可自行保存。原文含問卷細節，**不要整包餵給 bot**。

## 如果 Hermes 不是 Nous Research 的 Hermes Agent
`AGENTS.md`、`history/` 與 `skills/` 內的 Markdown 是通用格式，貼進任何 bot 的「系統提示」或「知識庫」都能用，只有放置位置要改。
